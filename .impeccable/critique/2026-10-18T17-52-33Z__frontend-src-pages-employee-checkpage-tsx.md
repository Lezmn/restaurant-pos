## Design Specificity Verdict

**LLM assessment:** ทั้งสองหน้ายังเป็น "admin ทั่วไป" ที่หยิบไปใช้กับระบบไหนก็ได้ Check คือตาราง CRUD หัวน้ำเงิน (`table-head` ซึ่งยังไม่ได้ยืนยันกับ Figma และไม่อยู่ในโลกสีส้มของแบรนด์) ส่วนช่วงเวลาที่สำคัญที่สุดของร้าน คือรับเงินจากโต๊ะ กลับเป็นลิงก์ตัวเล็กสีส้มในเซลล์ขวาสุด Manage เป็นกริดการ์ดสินค้าแบบหลังบ้าน e-commerce ไม่มีอะไรที่บอกว่าเป็นครัวที่ต้องปิดเมนูหมดกลางกะ จุดที่เป็นของร้านนี้จริง ๆ มีอยู่แล้วแต่ถูกซ่อน: สถานะสลิป PromptPay, คำเตือน "ยังเสิร์ฟไม่ครบ", ยอดลิ้นชักรายวัน

**Deterministic scan:** สแกนไฟล์ .tsx ทั้ง 9 ไฟล์ด้วย CLI ได้ 0 รายการ แต่เป็นการจับ regex อย่างเดียว ไม่ได้ตรวจ contrast จึงเป็นตัวเลขที่ต่ำกว่าจริง ตัวตรวจในหน้าเว็บเจอ **low-contrast 10 จุดบน Check และ 9 จุดบน Manage** ที่หนักสุดคือ ตัวขาวบน `brand-200` 2.0:1 (นาฬิกา), ตัวขาวบน `brand-300` 2.3:1 (แท็บที่เลือก, "+ เพิ่มเมนู"), ตัว `brand-300` บนครีม 2.2:1 (ยอดเงินสดในแถบลิ้นชัก), ข้อความ empty state เทา 2.6:1 ส่วน `brand-400`/`danger`/`promptpay` บนขาว 4.2–4.4:1 พลาดเกณฑ์ 4.5:1 นิดเดียว ไม่มี false positive detector จับเรื่องที่ผมพลาดได้หนึ่งเรื่อง คือนาฬิกาและแถบลิ้นชัก

**Visual overlays:** ฉีด detector สำเร็จ overlay แสดงในแท็บ **[Human]** ของ browser pane (หน้า Manage ค้างอยู่) ปิด helper server แล้ว

## Overall Impression

ตรรกะทางธุรกิจแน่นมาก (กันจ่ายก่อนเสิร์ฟ, ล็อกยอดด้วย `expectedTotal`, แยกยอดเก็บจริงกับเงินที่รับมา, ยกเลิกบิลต้องมีเหตุผล) แต่ UI ไม่ได้สะท้อนว่างานไหนสำคัญ จุดที่น่าทำมากที่สุดคือทำให้ "เก็บเงินโต๊ะนี้" เป็นปุ่มใหญ่ที่สุดในหน้า Check และทำให้ "ปิดเมนูหมด" ใน Manage เร็วพอสำหรับครัวที่มือไม่ว่าง

## What's Working

1. **การกันความผิดพลาดเรื่องเงิน** แจ้ง "ยังเสิร์ฟไม่ครบ (เหลือ N ออเดอร์)" ก่อนจะกด, แยก "ราคาที่เก็บจริง" กับ "รับเงินมา (ไว้คิดเงินทอน)" และคำนวณส่วนลด/เงินทอน/เงินขาดให้ทันที ตรงกับงานแคชเชียร์จริง
2. **ConfirmDialog ของ Manage** บอกผลที่ตามมาก่อนลบ ("ถ้าเมนูนี้เคยถูกสั่งไปแล้วจะลบไม่ได้ ให้ปิดสวิตช์แทน") เป็นคำแนะนำที่ถูกต้องและอยู่ถูกจังหวะ
3. **สวิตช์พร้อมจำหน่ายมีพื้นที่กด 40×56px** และใช้ `role="switch"` + `aria-checked` ถูกต้อง

## Priority Issues

**[P1] Check เงียบเมื่อดึงข้อมูลไม่ได้**
- **Why it matters:** ตอนตรวจครั้งแรก API ล่ม หน้า Check ขึ้น "ยังไม่มีโต๊ะที่เปิดอยู่" และ "จำนวนโต๊ะที่ว่าง 0 โต๊ะ" ส่วนแถบลิ้นชักหายไปทั้งแถบ แคชเชียร์จะเข้าใจว่าไม่มีโต๊ะค้างจ่าย ทั้งที่จริงมีโต๊ะ 1 ค้าง ฿50
- **Fix:** แยก loading / error / empty ให้ชัด ใช้ `isError` จาก `useSessions`, `useOrders`, `useCashClosePreview` แสดงแถบ "เชื่อมต่อระบบไม่ได้ ข้อมูลอาจไม่ล่าสุด" พร้อมปุ่มลองใหม่ ห้ามแสดง empty state ตอนที่ error
- **Suggested command:** `/impeccable harden`

**[P1] ปุ่มรับเงินของ Check ไม่ดูเหมือนปุ่ม และหลุดจอบนมือถือ**
- **Why it matters:** "เก็บเงิน" เป็นลิงก์ 14px สีส้ม/ฟ้าตามวิธีจ่าย ส่วน "ปิดโต๊ะ" เป็นตัวเทา ทั้งสองดูเหมือนข้อความสถานะ ที่ 375px ตารางกว้าง 600px คอลัมน์ปุ่มจึงอยู่นอกจอ ต้องเลื่อนแนวนอนก่อนถึงจะรับเงินได้
- **Fix:** ทำเป็นปุ่มจริงตาม DESIGN.md (พื้นทึบ สูงอย่างน้อย 44px ข้อความ "รับเงิน ฿50") บนจอแคบเปลี่ยนแถวตารางเป็นการ์ดโต๊ะ (เลขโต๊ะใหญ่ ยอด ปุ่มเต็มความกว้าง) ใช้ป้าย/สีแยก "รอเช็คบิล" ออกจากตัวปุ่ม
- **Suggested command:** `/impeccable layout` แล้วตามด้วย `/impeccable adapt`

**[P1] สีส้มกับตัวขาว contrast ไม่ผ่าน**
- **Why it matters:** แท็บที่เลือก (Check/Manage), "+ เพิ่มเมนู", นาฬิกา ใช้ตัวขาวบน `brand-300`/`brand-200` ที่ 2.0–2.3:1 ซึ่งต่ำกว่าเกณฑ์ตัวใหญ่ 3:1 ด้วยซ้ำ ยอดเงินสดในแถบลิ้นชัก `brand-300` บนครีมได้ 2.2:1 ทั้งที่เป็นตัวเลขเงินที่ต้องอ่านให้ถูก
- **Fix:** ทำตาม DESIGN.md: พื้นทึบที่มีตัวขาวใช้ `brand-400` ตัวเลขเงินสดใช้ `brand-400` หรือดำ ข้อความ empty state ใช้ `gray-500` แทน `gray-400`
- **Suggested command:** `/impeccable polish`

**[P2] กล่องรับเงินใช้ภาษาปุ่มขัดกับทั้งแอป**
- **Why it matters:** ในกล่องรับเงิน "ยกเลิก" เป็นแดงทึบ (ดูเหมือนการลบ/ยกเลิกบิล) และ "บันทึก" เป็นเขียว ซึ่งต่างจาก ConfirmDialog ที่ปุ่มย้อนกลับเป็นขอบเทาและปุ่มยืนยันเป็นสี ช่องกรอกเป็นพื้นเทามุม 4px ต่างจากฟอร์มอื่น ปุ่ม "บันทึก" ไม่บอกยอดเงิน ทั้งที่เป็นจุดที่ควรมั่นใจที่สุด
- **Fix:** ปุ่มซ้าย "ย้อนกลับ" แบบ secondary ปุ่มขวา "รับเงิน ฿50" แบบ primary และให้ยอดในปุ่มอัปเดตตามช่อง "ราคาที่เก็บจริง" ช่องกรอกใช้ `input-field` ตาม DESIGN.md
- **Suggested command:** `/impeccable clarify` แล้วตามด้วย `/impeccable polish`

**[P2] การ์ดเมนูใน Manage ทำงานหลักช้า และงานอันตรายเด่นเกินไป**
- **Why it matters:** ครัวเข้า Manage เพื่อปิดเมนูที่หมด แต่ทุกการ์ดมีปุ่ม "ลบ" สีแดงเด่นเท่า "แก้ไข" (7 เมนูก็มีปุ่มแดง 7 ปุ่ม) กดสวิตช์ตัวเดียวแล้วสวิตช์ทุกตัวถูก disable จนกว่า API ตอบ (`setAvailability.isPending` ใช้ร่วมทั้งกริด) ปิดหลายเมนูติดกันจึงสะดุด
- **Fix:** ย้าย "ลบ" ไปไว้ในกล่องแก้ไข (ล่างสุด แยกโซน) ให้ pending เป็นรายเมนู เมนูที่หมดให้การ์ดจางทั้งใบพร้อมป้าย "หมด" ที่เห็นจากไกล และเพิ่มตัวกรอง "เฉพาะที่หมด"
- **Suggested command:** `/impeccable distill` แล้วตามด้วย `/impeccable layout`

## Persona Red Flags

**แคชเชียร์ช่วงเที่ยง (เฉพาะโปรเจกต์นี้, STAFF):** มีลูกค้ายืนรอจ่าย 3 โต๊ะ ต้องหาเลขโต๊ะในตารางที่ไม่เรียงลำดับ ไม่มีช่องค้นหา ต้องหาลิงก์ "เก็บเงิน" ตัวเล็กที่ขวาสุด ปุ่มบันทึกในกล่องไม่บอกยอด ต้องเหลือบกลับไปดูหัวกล่อง ถ้าเน็ตสะดุด หน้าจะบอกว่าไม่มีโต๊ะค้าง

**ครัวกลางกะ (เฉพาะโปรเจกต์นี้, KITCHEN บนแท็บเล็ต):** วัตถุดิบหมูหมด ต้องปิด 3 เมนู กดสวิตช์แรกแล้วอีกสองสวิตช์จางจนกว่าเซิร์ฟเวอร์ตอบ มือเปียกอาจพลาดไปโดนปุ่ม "ลบ" สีแดงที่อยู่ใต้สวิตช์ห่างแค่ ~12px (กล่องยืนยันยังกันไว้ได้) สถานะหมดแสดงแค่ตัวเทา 14px ในการ์ด มองจากไกลไม่เห็น

**Sam (Accessibility):** ตัวขาวบนส้ม 2.0–2.3:1 ทั้งแท็บที่เลือก ปุ่มเพิ่มเมนู และนาฬิกา คำอธิบายเงื่อนไขอยู่ใน `title` ซึ่ง screen reader อ่านไม่สม่ำเสมอ ส่วนใหญ่ไม่มี `focus-visible` ring (ปุ่มเก็บเงินมี ring แต่ปิดโต๊ะ, แก้ไข, ลบ, ชิปไม่มี) ความหมาย "เงินขาด/เงินเกิน" ใช้สีร่วมกับข้อความ ซึ่งดีอยู่แล้ว

**Alex (Power User):** ไม่มีคีย์ลัดหรือค้นหาเลขโต๊ะ ไม่มีปิดเมนูแบบหลายรายการ หน้า Manage มีช่องค้นหาแต่ไม่โฟกัสอัตโนมัติ
